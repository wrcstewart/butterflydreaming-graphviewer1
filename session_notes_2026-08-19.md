## 2. Auto-Player was broken by a sticky boolean

Reported as "opening a module node doesn't engage the Player radio any more".
The feature (`140941c`, 2026-08-09) had never been removed; it fired on the
`false → true` edge of a single session-lifetime flag, `prevHasModule`.

`hasModule` is true if the module directive is in the reading node **or in the
top Current card**. Once any module script lands in that card the flag pins true
for the whole session — and both the ↓ arrow and the return-from-standalone flow
put one there by design. So the edge never came round again. It worked on a
fresh page load and died as soon as you actually used a module, which is exactly
the pattern that makes a bug look intermittent.

Fixed in `624cce4`: the node and card paths are computed separately and the
switch keys off the **module node's id**, so a second module node fires, and so
does returning to the first after reading something else. "Manual Nodes
selection is respected" still holds, now for a sound reason — while you stay on
the node its id already equals the stored key.

**Diagnostic technique worth keeping:** the running server's stdout goes to
`/private/tmp/bd_server.log`, and BD forwards its client console into it. A
transition-only `console.log` in the suspect branch settled in one reload what
an hour of reading could not. **Module iframes are NOT covered** — BD relays
only its own window (see §4).

## 4. The two traps, restated

Both are in spec §9a. In one line each:

- **Only the first N rows of an injected list appear** → the loop threw at item
  N. Do not go looking at CSS height/overflow first.
- **A module iframe's console errors do not reach the server log.** Reproduce
  the module's top-level execution order under node: slice the script from its
  data block through the injection loop, append the hoisted helper, stub
  `document.createElement`/`appendChild`.

## 5. Consent model (settled)

Personal saving/export is unrestricted by design. **Only writing to the BD graph
database requires partner agreement.** Save wav / Save midi were hidden in BD
(`17b123c`) and reverted within the hour (`47c4f3e`) once it was clear the
standalone escape hatch made the gate theatre: a user can jump out carrying the
script and save there. Don't gate export affordances; spend the effort at the
DB-write boundary.
